## Answers to the brief, in short
1. Adapter: the layout record never selects a layout; it is only compared with the build's `DUP_LAYOUTS`
   (`env.rs:556-566`), a differing or unreadable record refuses the open (`error.rs:191-206`: a record not of 3
   bytes is "the unreadable record"), a missing table or row opens (documented lenient, `env.rs:328-336`).
   `create_tables_for` creates the record table, each table and its record row in one `RwTxn` and commits once
   (`env.rs:596-614`): the engine's commit is atomic, so a crash leaves neither. `RO` opens through
   `Env::open_read_only`, then `txn.open_table(LAYOUT_TABLE)` returns `None` for a file without the table and the
   check is skipped (`env.rs:556`). `tx::guarded` (`tx.rs:64-66`) wraps all four decode sites
   (`tx.rs:71`, `cursor.rs:794,803,811`); the closure captures only page slices, the engine call has already
   returned (no `UnwindLatch` involved), the write transaction's `parking_lot::Mutex` guard sits outside the
   catch and parking_lot does not poison, the cursor's engine cursor and pool slot are untouched (the decode runs
   after the move). No TN profile sets `panic = "abort"` (`.cargo/config.toml`, root `Cargo.toml` have none;

## Considered and rejected
- **A damaged or missing layout record selecting another layout.** The record is read only to be compared
  (`env.rs:557-565`); the layout comes from `DUP_LAYOUTS` through `tables.layout(name)` (`env.rs:414-417`) and the
  engine's catalog form is checked by `TableEntry::open` (`env.rs:362-373`) for every table found. A record of any
  other content, length included, is `layout_mismatch` → `MDBX_INCOMPATIBLE` (`error.rs:191-206`). Pinned by
  `a_file_whose_recorded_layout_differs_is_refused_at_open` for RW and RO, a changed W, a changed form, the row put
  back, and the row deleted. (The "v1 file" of the brief is a reth storage-layout concern, `TN_LAYOUT_VERSION`,

  (`env.rs:596-614`); an error in the loop returns before the commit and drops the transaction (abort).
